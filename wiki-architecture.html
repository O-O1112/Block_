Engine Architecture

To truly understand how Block achieves polyglot orchestration without a virtual machine, we need to dive under the hood. Block is built around a high-performance C# Orchestrator.

The C# Orchestrator & Zero-IO Architecture

At the core of the Block engine is the Orchestrator, written in high-performance C# (.NET). When you execute a script, the Orchestrator performs the following lifecycle:

  1. Lexical Analysis & AST Parsing: The script is parsed into an Abstract Syntax Tree (AST), separating native Block syntax from embedded polyglot blocks (e.g., <python>, <js>, <rust>).
  2. Zero-IO Scope Injection: Unlike legacy file-based IPC, Block v2.0 utilizes direct global scope variable injection. Variables are serialized into standard I/O streams and injected straight into global execution scopes (e.g., globalThis or globals()) without reading/writing disk files.
  3. Subprocess Spawning: When the AST evaluator encounters a polyglot block, it spawns a native subprocess (e.g., python.exe, node.exe, or rustc).
  4. Stream Pipeline & Auto-Install: In Block+, if a required runtime environment is missing, the Orchestrator automatically invokes Winget to install it in the background. State is synced back upon process termination.

3-Stage Masking Security

Because Block executes native code and passes variables across process boundaries, security is a top priority. Block employs a 3-Stage Masking system to prevent injection attacks during state serialization:

  • Stage 1 - Regex Validation: Variable names are strictly validated against a regex pattern (^[a-zA-Z_][a-zA-Z0-9_]*$) to ensure they cannot contain execution payloads.
  • Stage 2 - Type Assertion: The Orchestrator enforces strict JSON-type assertions during cross-boundary transit. Only Primitives (Strings, Numbers, Booleans) and basic Arrays/Objects are passed.
  • Stage 3 - Subprocess Isolation: Each polyglot block is executed in an ephemeral, isolated subprocess. Code execution errors immediately kill the subprocess without crashing the Orchestrator.

Performance Considerations

With the Zero-IO Direct Scope Injection architecture, context-switching overhead is reduced to near-zero (~1ms to ~5ms), making polyglot block execution blazing fast and suitable for real-time web servers, automation, and microservices.
